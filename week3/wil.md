애플리케이션은 계층형 아키텍처로 구성되며, 이는 Browser, Controller, Service, DAO(Repository), DB 순으로 연결됩니다. Controller 계층은 HTTP 요청을 받아 가장 먼저 처리하며, DTO를 사용해 서비스 계층과 데이터를 교환한다. Service 계층은 애플리케이션의 비즈니스 로직을 담당하며, 컨트롤러와 레포지토리 사이의 다리 역할을 한다. Repository 계층은 데이터베이스(DB)에 접근하여 CRUD (Create, Read, Update, Delete) 작업을 수행하는 계층이다. Java 애플리케이션은 JDBC API를 통해 SQL을 직접 DB에 전달하여 데이터를 처리했다. 그러나 이 방식은 반복적인 SQL 코드 작성, SQL에 의존적인 개발, 그리고 객체와 DB 간의 패러다임 불일치라는 문제점을 야기했다. 이러한 문제를 해결할 수 있는 ORM 방식이 있다. ORM은 객체와 관계형 데이터베이스의 데이터를 자동으로 매핑(연결)해주는 것이다. JPA는 자바 진영의 ORM 기술 표준이며 자바에서 객체를 데이터베이스에 저장하고 관리하기 위한 인터페이스와 기능을 제공하는 API이고 대표적인 JPA 구현체는 Hibernate가 있다. EntityManager는 엔티티 객체를 데이터베이스와 연결해주는 창구 역할을 한다. JPA의 동작 핵심은 영속성 컨텍스트이다. 엔티티 매니저는 엔티티 객체를 이 컨텍스트 내의 1차 캐시에서 관리하며, 이는 중복 조회를 방지하고 성능을 최적화한다. 데이터 변경은 엔티티 객체 수정만으로 이루어지고, 변경감지를 통해 추적됩니다. 실제 DB로의 반영은 플러시 과정을 통해 트랜잭션이 커밋될 때 일괄적으로 처리된다.
