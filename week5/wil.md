스프링은 Java 기반의 프레임워크이며, Java의 가장 큰 특징인 객체 지향 프로그래밍(OOP)을 적극적으로 활용할 수 있게 도와준다. 객체 지향 프로그래밍이란 프로그램을 여러 독립적인 객체들의 조합, 즉 레고 블록처럼 조립해 전체 시스템을 구성하는 방식으로 이해하는 패러다임이다. 이 방식은 프로그램을 유연하고 변경하기 쉽게 만들어, 실제 현업에서도 대규모 소프트웨어 개발에 널리 쓰인다.

객체 지향의 대표적인 네 가지 특징은 추상화, 캡슐화, 상속, 그리고 다형성이다. 추상화는 공통된 속성과 기능만 뽑아 정의하는 것이고, 캡슐화는 관련 데이터와 기능을 하나로 묶어 외부로부터 보호하는 것이다. 상속은 기존 코드를 물려받아 재사용하는 특징이며, 다형성은 하나의 역할을 다양한 방식으로 구현할 수 있다는 성질을 의미한다. 특히 다형성은 객체를 사용하는 쪽이 역할(인터페이스)만 알고 구체적인 구현체를 몰라도 되게 만들어 프로그램의 변경과 확장을 매우 쉽게 한다.

예를 들어 데이터 저장소를 메모리로 할지, 데이터베이스로 할지는 나중에 변경될 수 있으므로 ‘저장소’라는 역할을 먼저 정해두고, 이를 구현한 MemoryRepository, JpaRepository 같은 구현체를 필요할 때 바꿔 끼울 수 있도록 만든다. 이를 위해 인터페이스(역할)를 만들고, 해당 인터페이스를 구현하는 클래스를 통해 유연함을 확보한다.

이러한 객체 지향 철학을 바탕으로 좋은 설계를 하기 위해서는 SOLID 원칙이 중요하다. 첫 번째인 단일 책임 원칙(SRP)은 한 클래스는 하나의 책임만 가져야 한다는 원칙으로, 변경 이유가 여러 개 생기지 않게 하여 유지보수를 쉽게 한다. 두 번째 개방-폐쇄 원칙(OCP)은 기존 코드를 수정하지 않고 기능을 확장할 수 있어야 한다는 원칙이다. 세 번째 리스코프 치환 원칙(LSP)은 부모 타입 자리에 자식 타입을 넣어도 프로그램이 정상 동작해야 한다는 의미다. 네 번째 인터페이스 분리 원칙(ISP)은 클라이언트가 사용하지 않는 큰 인터페이스보다 목적별로 잘게 나뉜 인터페이스에 의존하도록 하여 대체 가능성과 명확성을 높인다. 마지막으로 의존관계 역전 원칙(DIP)은 구현 클래스가 아닌 추상화(인터페이스)에 의존해야 한다는 원칙으로, 변경에 강하고 유연한 구조를 만든다.

하지만 다형성만으로는 SOLID 원칙을 완전히 만족시키기 어렵다. 이를 해결해주는 것이 바로 스프링의 핵심 기능인 IoC(제어의 역전)과 DI(의존성 주입)이다. IoC는 객체 생성과 관리 주체가 개발자가 아니라 스프링 컨테이너로 넘어가는 개념이며, DI는 필요한 객체를 직접 생성하지 않고 외부에서 주입받는 방식이다. 스프링 컨테이너는 필요한 객체를 미리 한 번만 생성하여 재사용하는데, 이를 스프링 빈(Spring Bean)이라고 부르며 대부분 싱글톤으로 관리된다.

스프링 빈을 등록하는 방법에는 두 가지가 있는데, 설정 파일을 통해 @Configuration + @Bean 으로 수동 등록하는 방법과, 컴포넌트 스캔(@ComponentScan)을 이용해 @Component, @Service, @Repository, @Controller 같은 어노테이션이 붙은 클래스를 자동 등록하는 방식이 있다. 스프링 컨테이너는 등록된 빈들 중에서 필요한 타입의 객체를 @Autowired로 자동 주입할 수 있고, 의존성 주입 방식은 생성자 주입, 수정자 주입, 필드 주입 등이 있지만 가장 권장되는 방식은 생성자 주입이다. 생성자 주입은 불변성을 보장하고, 의존 관계를 명확하게 드러내며, 테스트하기에도 유리하기 때문이다.

만약 같은 타입의 스프링 빈이 둘 이상 존재할 경우에는 @Qualifier로 이름을 지정하여 특정 빈을 선택하거나, @Primary를 사용해 기본적으로 먼저 선택될 빈을 지정할 수도 있다. 또한 기능 확장 가능성이 처음부터 명확하지 않다면 무리하게 인터페이스를 도입하기보다, 우선 구체 클래스로 구현하고 확장 시점에 리팩터링하는 것도 좋은 전략이라는 점도 강의에서 다뤄졌다.
